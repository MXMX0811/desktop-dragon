## 谁负责哪些文件

| 内容 | 修改位置 |
| --- | --- |
| 静态原画、拆图、补绘、姿势、网格、角色控制器与动作时序 | 制作目录 |
| 动画导出模块、贴图、校色、通用表情/终端效果 | 制作目录；确认后整体交付到仓库 `assets/` |

| 接入方式、产品规格、软件测试 | 软件仓库 |

交付使用实际文件，不用指向制作目录的符号链接。运行时不会读取旧工作区的文件。原制作目录保留完整绘制历史。

## 统一目录

每个已交付状态和形态使用 `assets/animations/{state}/{form}/`：

- `scene.js`：该形态的动画入口。
- `textures/`：该形态使用的专有贴图。
- 控制器、姿势、网格和绘制模块按需与入口并列。已有合并运行模块可直接作为 `scene.js`，不用为了目录一致而拆开实现。

跨状态共用的控制器、校色、问号、终端、图稿和角色部件放在 `assets/shared/`；实际共用的坐姿身体、翅膀、尾巴和眼部素材只保留一份。第三方运行库及许可证放在 `assets/vendor/`。形象参考放在 `assets/references/`。

目录和资产文件名使用语义名称，不带 `redraw`、制作版本或候选后缀。不存在的形态不创建空目录，不通过兼容层保留旧资源地址。`app/runtime/`保留软件宿主、状态策略和交互页面。

## 一次交付的顺序

1. 在制作目录完成动作，按设计手册检查常驻、点击、等待、返回、被打断和目标尺寸。
2. 获得用户对具体版本的确认；记录源路径和确认范围。修正后沿用版本也需说明，不能把旧的确认解释为所有后续候选自动通过。
3. 导出该动作实际使用的运行模块、贴图、共同部件和校色。不复制无引用图片、制作工具、历史 QA、依赖目录或私人会话数据。
4. 在软件仓库对应资产目录整体更新，同步模块导入和素材相对地址；更新 `asset-delivery.json` 和 `docs/asset-catalog.md`。交付清单的目标路径使用仓库语义名称，来源路径保留制作区相对目录、真实文件名与版本，外部根目录使用脱敏占位符。
5. 从仓库自身启动预览，检查依赖加载、常驻/等待/交互和已有状态切换。检查通过后再作为软件当前资产提交。

`asset-delivery.json` 是本次交付清单，不是运行时配置，也不是自动同步机制。无需常驻同步、迁移脚本或文件哈希。软件对资产的调用接口若需要改变，在制作目录一次同步修正后重新交付，不添加版本兼容包装。

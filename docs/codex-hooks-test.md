# Codex hooks 首轮可行性实测

本文保留首轮CrossPet日志观察结果。独立接收器已于2026-11-02实现并完成真实CLI测试，当前接入说明以[独立接入记录](codex-hooks-implementation.md)为准。

2026-11-01，macOS，当前原生客户端，随应用安装的CLI版本`0.166.0-alpha.5.1`。

## 结论

**可以通过hooks取得真实的会话生命周期和工具活动事件。** 本次直接观察当前对话产生的事件，验收范围为钩子事件本身。现有CrossPet已安装并信任的hook足以完成首轮可行性验证，因此没有修改全局配置或信任记录。

本次结果证明钩子确实触发，并非把人工JSON输入脚本后当作客户端验证。它不等于已经取得完整内部状态：该轮证据不包含精确并发归属、审批等待解除、成功完成和用量。

## 怎么测试

读取`~/.codex/hooks.json`及其指向的CrossPet记录器，核对当前事件注册。用当时的诊断脚本`hook-check.mjs`在75秒和20秒两个窗口观察既有`events/codex.jsonl`的新增记录，分别取得11条和5条记录，窗口内未发现日志断档。窗口前的保留记录与窗口内新增记录分开保存。

随后在当前聊天中实际执行：读取测试文件、短命令及异步命令、通过apply_patch修改测试文件、网页工具、无副作用的MCP调用，以及一个只读审查子代理。独立观察器只读取钩子落盘文件，不访问会话正文，不发消息，不输出批准/拒绝决定。

可复查的脱敏元数据位于[实测记录](qa/codex-hooks-2026-11-01.json)；完整本地观察报告位于`.local/hooks/`，该目录不进入Git。公开摘要将CrossPet短会话标识替换为稳定匿名标签，时间改为相对于首次新增事件的秒数；保留事件顺序、间隔与配对关系。这些标签不是原始会话ID。不新增哈希，不保存命令正文、提示词或工具结果。

## 正式接收器采用的规则

1. **独立接收原始hook元数据。** CrossPet诊断日志将工具名转小写并截断，只有短会话标识和“是否有turn_id”，缺少原始`turn_id`、`tool_use_id`、`agent_id`。它适合验证事件到达，不足以作为多会话汇总的数据接口。正式接收器应保留这些归属字段，仍不保存正文。
2. **逐调用归并。** 本轮存在一个异步Bash结果未返回时，MCP和网页工具已经完成的重叠情况。某个PostToolUse不能把整轮改成“思考”或完成。异步命令的Post还可能在write_stdin取得结果时才送达，不能将前后hook时间差直接当成真实执行耗时。
3. **区分观察事实与动画解释。** CrossPet的`running/searching/thinking`是它依据工具名做的分类，不是Codex输出的统一状态枚举。实际思考内容、思考进度以及准确完成百分比本轮均未取得。
4. **审批依赖完整生命周期。** PermissionRequest表示准备询问，可能被其他hook处理；仅此事件不足以证明真实等待开始及解除。Stop也可能触发继续运行，不能单独作为成功完成证据。[OpenAI Hooks文档](https://learn.chatgpt.com/docs/hooks)
5. **不依赖CrossPet的超时淘汰判断完成。** 它的会话表会清理长时间无事件的项，这只是表现策略。长任务无事件应当保持未知，而非推断结束。
6. **接收输入不能一直等EOF。** 现有实现记录了部分宿主写完JSON后不关闭stdin的情况；独立接收器须在获得完整JSON后及时退出，并做相应验证。

正式接收器保留完整调用归属，接入PermissionRequest和SessionEnd，通过Codex正式hooks审阅流程信任精确命令。基础CLI、原生聊天、并发工具与单个子代理的证据见[独立接入记录](codex-hooks-implementation.md)。自动待确认对应已核实的异步提问与回答回调；权限审批和复杂嵌套归属不在这轮可行性证据内。

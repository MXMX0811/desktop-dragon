# 点击信息与预置对话设计

2026-11-03讨论稿。本轮仅调整人物尺寸和双云参数；本方案不改动现有点击、会话面板或来源采集。

## 一次互动

1. 气泡隐藏时点击人物：原人物反馈与双云环绕照常播放，头顶出现信息气泡，显示6秒。
2. 气泡显示期间再次点击：切换到当前状态的下一句预置台词，每句显示5秒；再次点击重新计时。台词按顺序轮换，避免立即重复。
3. 超时后气泡收起。下次点击从最新信息重新开始，不延续上一轮台词。
4. 开始拖动、飞行、变身、隐藏人物或打开右键菜单时收起并重置。普通任务状态变化时，信息摘要更新但不重置计时；已显示台词保留到超时，后续点击按新状态取句，避免阅读/工作频繁切换使气泡来不及读完。
5. 休眠点击仍优先完成唤醒，气泡内容采用唤醒时的信息，不额外重播或打断哈欠。

三连击与台词切换共用现有420ms连击判定。第一下立即反馈并显示信息；快速第二下暂缓推进台词，若第三下到来则取消该次台词、收起气泡并变身。没有第三下时推进一句。间隔超过连击窗口的普通再次点击直接换台词。保持一个气泡，不堆叠，不排队播放过时消息。

## 信息内容

信息最多2–3行，首要内容为账户额度与重置时间，其次为当前活动摘要。字段按真实来源是否提供决定，不通过工具次数或运行时长推算额度。

示例（均为虚构数值）：

> 账户额度剩余 72% · 约2小时后重置  
> 活动会话 2 · 工具 3 · 子代理 1

多个额度窗口按接口提供的名称与时长区分，例如短时窗口和周窗口。账户额度只显示一次，不把同一账户多个会话的比例相加。百分比与余额采用来源自身单位，不把积分解释成金额或可发送消息数。

现有`desktop/main/sessions.mjs`提供活动会话、工具、子代理数量、模型、工具类别、采集开关和最近事件时间。可直接用于如下摘要：

| 情况 | 信息 | 后续点击台词示例 |
| --- | --- | --- |
| 待机，采集正常 | 目前没有观察到活动会话；账户额度 | “要不要一起歇一会儿？” |
| 阅读 | 正在读取或检索 · 活动工具数 | “等我把这一页看完。” |
| 工作 | 活动会话、工具与子代理数 | “我在呢，继续忙你的吧。” |
| 思考 | 已观察活动会话数；有子代理则显示数量 | “让我再想一小会儿。” |
| 绘图动作展示 | 正在预览绘图动作；账户额度 | “这一笔画在这里怎么样？” |
| 待确认动作展示 | 正在预览待确认动作 | “我先在这里等一会儿。” |
| 采集关闭 | 状态采集已关闭 | “我在这里陪着你。” |
| 本次无事件或读取失败 | 等待活动数据／状态读取失败 | 使用一般陪伴台词，不声称正在工作或工作成功 |

显示真实活动时不把手动选中的姿态当作来源事实。`Stop`只代表观察到停止，`PermissionRequest`不能独立证明用户正被请求批准。确认等待状态必须有对应的真实来源事实。会话标题、正文、绝对文件路径不放入简短气泡。

额度目前不在钩子快照中。官方[App Server额度接口](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)提供只读`account/rateLimits/read`与`account/rateLimits/updated`，包含`usedPercent`、`windowDurationMins`、`resetsAt`及额度桶标识。剩余比例由已返回窗口的`100-usedPercent`计算。窗口名称按真实返回值生成；[套餐说明](https://learn.chatgpt.com/docs/pricing#what-are-the-usage-limits-for-my-plan)中本地与云端共享额度，不能固定假设所有账户都具有相同的短时和周窗口。

正式实现前验证当前安装的Codex版本、认证方式及官方查询入口。额度归属必须与所显示的账户明确对应；文档存在该接口不代表能直接连接任何已运行客户端。仅取得该账户的额度快照，不读取凭据、会话正文或执行任何会话控制。额度缺失时不画进度条，并明确显示“账户用量暂无数据”；旧快照标明更新时间。

## 呈现

- 使用浅色圆角气泡、细紫灰描边和指向头部的小尾尖；宽约200–240px、字号13–14px，文字尺寸不随人物缩小。
- 首选头顶空位，避开龙角、问号和两朵小云。靠屏幕顶端时放到朝屏幕内侧的一边，并约束在当前显示器工作区。
- 进入约180ms、退出约160ms，以淡入淡出配合4px上下位移；切换文字约100ms，不做逐字打字，以便短时间读完数据。
- 沿用现有不激活的透明窗口，气泡仅计入显示范围，不加入鼠标命中区；鼠标穿透，点击人物不抢走原工作窗口焦点。
- 气泡只供短时查看。完整会话面板保留在右键菜单，信息查询和人物对白都不控制会话。

交互参考[Material UI Snackbar](https://mui.com/material-ui/react-snackbar/)短时、非模态提示与自动收起方式，以及[Windows TeachingTip](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/dialogs-and-flyouts/teaching-tip)靠近目标元素的定位方式。本项目沿用现有DOM、CSS和Web Animations，不为这一气泡引入新的UI框架。

## 实现分工

- `desktop/main/`：在已核实的官方入口上增加独立只读额度查询，输出账户标识、额度窗口和获取时间。首次信息点击按需查询；60秒内复用同账户快照，气泡关闭不轮询。
- `desktop/preload/`：只提供额度快照的查询接口，不开放通用请求或会话控制。
- `app/desktop/`：一个气泡组件管理显示、定时收起、位置和内容；纯内容函数根据快照生成信息，固定台词表按状态取句。现有点击处理串接该组件和三连击判定。
- 动画层：沿用已经完成的点击、唤醒和双云动作，信息展示不承担任务状态变更。

实施时先完成“首点信息→再次台词→超时→首点重新信息”的最小完整交互，再接入已经验证的账户额度查询。所有展示与软件读数保持独立，读取失败不阻塞人物动作。

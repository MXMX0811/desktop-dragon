# 二维角色动作与分层素材设计手册

版本：2026-10-29。适用于桌宠、二维角色和固定视角的轻量 Live2D 式动画；覆盖 Q 版、正比、全身与半身、站坐卧、手持物和场景交互。

本文提炼设计方法。项目已经发生的问题放在第 9 节作为证据，具体画面与采用记录见状态图录（制作区：`<art-workspace>/dragon-pet/README.md`）。新动作直接填写[设计与交付模板](state-design-template.md)。当前运行层见 [runtime](../app/runtime/README.md)，系统建议与实际接入状态分别记录。

执行要求：本项目的角色绘制、拆分、补绘和动画修改均须遵循本文。精修前按模板明确动作、结构、遮挡与隐面，先跑通最难的一段运动；交付前检查中间帧和实际播放，并登记确切采用文件。适用于Q版、正比及其他姿态。

当前制作采用分层素材与实时动画。新增关键姿态用于解决视角、接触和可见面变化；增加图片数量本身不能保证动作平滑。2026-10-29用户已采用最新[Q版唤醒动作](wake-notes.txt)，本轮经验已归入下述通用规则与模板。

2026-10-31展示接入补充：动作被采用后，必须同时核对正式运行入口、单动作审阅入口和构建脚本。相邻的常驻与一次性动作共用同一生产控制器、渲染器与素材，审阅页只提供控制；不能只新增一个“最新动作”链接而让正式场景继续播放旧模型。当前导航只连接现用版本，历史对照明确标记。 替换角色主体时逐项核对常驻动作、点击反馈、休眠唤醒和待确认，不能只验证主动作：独立翅膀或尾巴层若被合回底图，旧交互会随之丢失。检查新一轮构建后旧场景不会被重新写回，并在运行页实播完整状态链路。

## 1. 先定义表演，再决定这一帧怎么画

**可动素材的交付单位，是一个能完成动作的角色部件组合，以及它的动作范围。** 一张漂亮的合成画面只能验证一个时刻。动画还要验证它如何到达这个姿势、如何离开、被打断后如何继续，以及移动后露出的东西是否完整。

设计顺序固定为：情境与意图 → 小尺寸动作轮廓 → 支撑与关节 → 关键姿势和动作范围 → 分层与隐面 → 简单往返动画 → 精修画面 → 次级运动与交互。

把要求放在三个层次，避免每次重新讨论：

| 层次 | 保存什么 | 可以复用到哪里 |
|---|---|---|
| 通用规律 | 接触、重心、关节连接、遮挡、动作阶段、图层归属、验收方法 | 任意角色、姿态与比例 |
| 角色设定 | 轮廓、比例、脸型、颜色、线条、饰品、惯用动作、性格 | 同一角色的各个状态；Q版与正比各有比例表 |
| 姿态与镜头 | 当前透视、关节位置、部件形状、接触点、动作极值、道具布局 | 同一个镜头和身体基础姿态的多个表情与动作 |

例如“注意到用户，停下手里的事，抬眼回应”是可复用的表演；抬头几度、肘在哪里、脸颊怎么变形，要由当前比例和镜头决定。

## 2. 静态画面与动画素材之间缺了什么

| 静态图已经回答的问题 | 动画还必须回答的问题 | 绘制阶段应增加的交付 |
|---|---|---|
| 当前看起来像这个角色 | 姿势变化后还是同一张脸、同一服装吗 | 角色设定板、统一比例、色板、线条基准、同镜头部件母版 |
| 这个姿势看起来成立 | 上一个姿势如何到达这里，关节是否够得着 | 起点、终点、接触改变时刻和最大伸展关键帧；衣物下的骨架草图 |
| 当前可见部分画完整 | 运动后原来藏住的地方是什么 | 动作范围内完整的部件、被遮挡区域、移走前景后的干净底层 |
| 一张图的前后关系正确 | 动作中哪些部件会交换前后 | 遮挡关系表、必要的前后子层、交接时刻 |
| 两张状态图分别好看 | 两端的轮廓、尺寸、材质能连续吗 | 共用部件；真正变化的表情、手势、视角替换件；统一坐标 |
| 某个表情有情绪 | 情绪如何出现、停留、恢复 | 眉、眼、口、头姿的协同设计；表情过渡关键帧 |
| 大图细节丰富 | 日常尺寸是否立即看懂，放大是否完整 | 目标大小预览、放大审图、动作幅度的屏幕尺寸检查 |
| 当前构图没越界 | 动作最大幅度、气泡和飞发是否越界 | 包含所有极值的画布范围与裁切边界 |
| 导出的 PNG 正常 | 最终程序中的纹理、蒙版、排序是否正常 | 用最终打包素材播放的完整循环、往返和中断验证 |

这里的额外工作包括结构草图、部件补全、清底、蒙版、锚点标定、动作编排、绑定和视觉验收。生成一张新状态图不能自动完成这些步骤；把平面 PNG 切成几块也不会自动得到隐藏的内容。

Live2D 官方的素材分离流程同样要求提前补画移动后会显露的区域，并保留可编辑的图层与蒙版。这为“先按动作准备素材”提供了成熟实践依据。本文的部件清单和验收规则来自本项目经验扩展。[官方素材分离说明](https://docs.live2d.com/en/cubism-editor-manual/divide-the-material/)

## 3. 任意姿态的结构设计

### 3.1 先画支撑与接触

先标地面、座面、桌面、握持面等接触位置，再画骨架和外形。判断角色重量由哪里承受；静止或缓慢支撑时检查重心是否落在支撑区域内。行走、跳跃等动态动作允许重心短时越出，由动量、重心轨迹和承重转换解释。飞行或悬浮也要明确运动意图和身体朝向，不能靠随机摆动表达。

站立和行走要标支撑脚与离地脚；坐姿要标骨盆、座面和双腿连接；卧姿要标身体与承托面的接触；靠、撑、托等动作要标手掌或肘部实际施力的位置。衣物、长发和尾巴不能代替这些结构说明。

**先确认骨架成立，再让衣物覆盖它。** 宽袖底部不是肘，裙摆鼓起处不是膝，头发下缘不是肩。必要时隐藏衣物和道具检查一次。不要因为最终看不见，就允许被遮挡的肢体断开或长度异常。

### 3.2 长度一致与透视一致一起检查

真实肢段的比例需要一致，屏幕上投影的长度可以随朝向变化。验收目标是关节连贯、透视合理、体积稳定；屏幕二维长度恒定不能代替人体结构判断。

每条肢体画出完整连接链：肩—肘—腕—掌，或髋—膝—踝—足。检查关节转向、肢段粗细和转折位置，而不只量两个端点。远近肢体受透视影响，但差异应能由同一个镜头解释。

双侧肢体须一起核对：上臂、前臂、掌块与肩根的粗细和长度应来自同一比例设定。不同手势可以有不同轮廓，但不能变成两种大小或画法的手。用衣物遮住的连接处也要画出结构草图，在抬起、经过胸前、接触目标及回落时分别核对。

双腿侧坐时，两条腿从骨盆两侧出发。膝和脚的位置由各自的髋、肢段长度、弯曲角度及深度共同决定，不能为了整齐把两膝和两脚硬排成上下两层。这条规则同样适用于交叉手臂、盘腿、蹲坐和跪坐。

所有说明明确采用“角色左/右”还是“画面左/右”。默认命名按角色自身左右，审图备注同时标注画面方向。

### 3.3 接触点要控制整条运动链

握住道具时，从握点推导手掌朝向，再协调腕、肘、肩；脚踩地时，从足部支点协调踝、膝、髋。不能只把手或脚拉到目标点，再把中间肢体拉长补齐。

位置对齐还不够。掌面与前臂方向、脚背与小腿方向必须连续，手指应真正围住握点。接触约束有阶段：接近、接触、保持、释放。把肘永远钉在桌上，或把脚永远钉在地上，也可能阻碍真实动作。

当接触到达范围不足时，先调整身体倾斜、肩髋位置、肘膝轨迹或道具位置，再考虑小幅透视修正。允许经过审图的软组织变形，避免肉眼可见的橡皮伸缩。

### 3.4 动作要有可读的阶段

一个动作通常包含准备、主要运动、接触或落定、短暂停留、恢复。按动作实际需要取舍，不必每次套齐五段。按键应有抬指、落下、触键、离开；招手应有抬臂、摆动、停顿、放下；伸懒腰应有蓄力、展开、保持、回收。

关键帧除了起终点，还要包含接触建立/释放、最大弯曲、最大遮挡变化、速度转向，以及换手势或视角的时刻。先把这些画清楚，动画才有可靠路径。

区分“绘制并校准过的关键姿态”和“从程序抽取的检查帧”。16张采样图只能展示已有实现，不能证明已补齐16个绘画姿态。手掌朝向、拇指位置或握持本身错误时，增加采样密度或减慢插值都无法修正。先检查低位、中段、终点的静态合成，再补转向、接触与显露边界处的姿态；需要新视角的部件就补绘，允许复用的部件则保持同一母版。

多张画稿的对应点必须指向同一物理位置。低位稿的上臂折痕不能对应高位稿的腕口；轮廓上相同序号或等分距离也不能证明对应。逐图确认袖口、接缝和附着点，隐藏关节明确标为推定。保存原生测量与运行接触修正，按画面实际姿态决定采用阶段，不能按提示词假定生成图已画到指定位置。

循环之间要有停顿和轻微节奏变化。呼吸、发丝、耳尾、衣摆不应永远同相位摆动；次级部件可以滞后于主体。日常陪伴动作保持克制，重要请求通过清楚的姿态和提示表达。

动作幅度应与角色服装和可用结构相称。长袖抬臂需要处理袖口、下垂布面与饰品的运动；若同一意图可用更小的动作清楚表达，可以在设计阶段改为单手掩嘴等动作。先确认表演，再确定所需隐面和部件，避免为了展示大动作反复扭曲衣物。

### 3.5 多关键姿态的时间与角速度

先标主要关节角度，再分配关键姿态的到达时间。不能把转角相差很大的几张图等分时间；相邻姿态的时间间隔应与实际转角、移动距离相称。一次连续抬手或放手的主要运动段大致匀速，只在起步、落定和真实的停顿处加减速，不要在每一张中间稿重新套缓入缓出。

单次主要转动可按累计转角安排中间姿态的到达时间，平移为主时按实际路径距离安排。相邻插值段在交接处共用速度，真实反向处才平滑降到零；避免过冲造成关节反折或布面翻面。主要关节的匀速不代表肘、腕的屏幕坐标必须走直线，也不代表所有关节采用同一速度。

跨关键姿态既要位置连续，也要速度连续。检查关节的局部角度与整个肢段的朝向，不能只看手掌坐标；肩的运动也会影响肘、腕的实际角速度。角度跨过正负180°时先展开，避免走长路或反转。回落、转向、接触改变时允许合理减速，匀速要求不等于全程僵硬直线运动。

速度连续仍可能在过短时段显得突然。把路径较长的靠近、转掌和释放分配足够时间，再看实际播放；不能只以关键点两侧导数相等判定自然。

用实际时间采样角度与速度曲线，并重点检查关键姿态前一帧、当帧、后一帧。主动作之外的袖摆、头发和装饰可以稍滞后，但不能拉开关节连接。插值避免过冲；在真实方向反转处平滑经过零速度。Spine 的 [Graph 文档](https://en.esotericsoftware.com/spine-graph)区分线性与贝塞尔曲线，可用其速度控制思路审查动作；本项目的数值范围由具体动作决定。

### 3.6 轮廓应在整个动作中保持清晰

每块素材分别看原图、提取后的独立层、移走该层后的底图、最终运动合成。确认完整的指尖、腕线、袖口、耳尖与发丝都归入正确部件；真正外轮廓要保留，内部切口不能额外描黑。底图应清除旧姿势的边线和阴影，补齐运动后显露的区域。

清底范围覆盖整个动作显露的区域，并逐一核对运行蒙版与打包裁切。仅扩大运行蒙版而沿用已裁空的纹理，仍会漏出旧手、旧纸页或旧衣物边。书本、袖片等独立层也须检查是否夹带邻近皮肤和衣料；清除这些像素时保护后方翅膀、发丝等真实轮廓，避免把邻层一并切掉。上述问题必须用实际合成图判断，骨长、网格和启动测试不能替代此项审图。

两张姿态分别清晰，不代表混合后的中间帧清晰。局部纹理混合前必须核对描线位置；出现双重轮廓、半透明肢体或颜色闪动时，先修复对应关系和分层。结饰、镜框等形状稳定的物件独立于大幅变形的衣料，使用同一母版保持轮廓；必要时补绘它们下面的衣料。

每个完整动作取10–20帧，覆盖正向和回落，并在关节交接、遮挡变化处加密。在日常尺寸检查动作可读性，在1000px与原生分辨率下核对边缘；同时查看深、浅背景。网格不翻面只证明几何的一项条件，不能替代对缺口、残留、断线、重影和肢体结构的实际审图。

## 4. Q版、正比、全身与半身如何复用

| 可直接共享的设计知识 | 每种形态需要重新标定的内容 |
|---|---|
| 动作意图、进入/退出条件、停顿与回应的顺序 | 头身比、躯干长度、四肢粗细、手脚大小、关节位置 |
| 支撑、接触、遮挡、部件归属原则 | 头重心、转轴、视线高度、道具握持位置 |
| 眨眼、呼吸、注视等参数的含义 | 参数极值、变形幅度、眼睑路径、脸部透视 |
| 动作调度、暂停、中断、优先级规则 | 为保持小尺寸辨识度而调整的动作幅度和持续时间 |
| 验收方法、素材清单和记录格式 | 纹理、网格、蒙版、裁区、绑定与视角替换件 |

Q版需要整体重建比例。只把正比头部放大，会让颈肩、上身、腿粗与重心不协调。可以简化体块、夸张表情和姿态轮廓，但关节连接和支撑仍要自洽。正比更容易暴露关节角度和体积变化，需要更克制的形变与清楚的受力。

Q版的结构正确不要求保留写实的关节刻画。采用肉球小手、圆脚等简化造型时，用掌块外形、拇指小突起和少量指尖线表现接触；腕与前臂、踝与脚的连接仍需成立。仅删除长手指的内部线条，外轮廓仍会显得写实。比例校准应同时观察头宽、下颌、颈肩、躯干及大小臂、大小腿、手脚；优先对照同角色的多个姿态，避免用长裙、发量或坐姿外接框误算头身比。参考库的文字比例目标与成图观察分开记录，自拟肢段标尺注明为设计建议。

补充手指细节前，先标出左右手、腕部朝向、掌面或手背、拇指连接的一侧，以及真正可见的指尖数量。内部任意添加C形或V形线条会被误读成手背上长出拇指；拇指被掌侧遮住时应保留遮挡，只画可见的指节。指缝从实际相邻手指关系推导，不能为凑足五指而增加外轮廓。对贴腮、掩嘴、握书、按键分别校验接触与朝向，细节必须跟随同一个完整手部部件。新增掌指细节不应引入第二套轮廓线或改动腕部连接。

共用一块完整手部素材时，仍须分别检查各状态的手势。把托腮或握物时的弯指轮廓直接旋回桌面，会得到位置正确却像握爪的打字手。先选能覆盖动作范围的放松掌指母材，再校准掌向、指节和接触；自然弯曲已经足够时，不额外卷指。腕饰与掌指可分别绑定，但整个腕口边缘必须接合，并清除新手素材夹带的旧腕饰。原稿已经触键时，以该指尖位置为落键下限，按键循环从抬指回到接触点，不能继续向下穿入静止键帽。

同一角色的两种比例保留身份特征与服装语言，分别制作比例板和动作范围。共享“抬头回应”这类动作含义，各自保存绑定和关键姿势；不要把一套像素坐标或网格强套到另一套比例。

半身构图仍要考虑镜头外的肩、肘、躯干方向及支撑。若手会进出画面，应画完整手和运动中可能出现的前臂；若下半身始终不可见且不影响动作，就无需为它制作运行时绑定。

大角度转头、背面转正面、坐到站等改变体积和可见面的动作，应在绘制时准备必要视角或中间关键姿势。小角度分层变形有明确的表达范围，超出范围就增加实际需要的视角素材。

## 5. 按运动需要拆部件

### 5.1 拆分判断

出现以下任一情况就考虑独立部件：与邻部件运动不同、需要单独遮挡、会改变表情或形状、需要独立光效。始终同动且没有独立遮挡需求的装饰可以合并。拆分数量由动作决定，不能把“层越多”当作质量目标。

| 类别 | 适合的控制方式 | 素材要求 |
|---|---|---|
| 刚性物体：镜框、硬质饰品、武器、道具外壳 | 平移、旋转、经过校准的整体透视 | 完整轮廓、明确支点，局部不能软拉；同一物体保持尺寸身份 |
| 肢体：头、上臂、前臂、大腿、小腿 | 关节驱动，局部受控形变 | 正确连接、重叠余量、真实关节轴；不把关节切口描成外轮廓 |
| 柔性物体：发束、裙摆、翼膜、尾段 | 根部约束与少量控制点 | 连续材质、明确固定区和可弯区；动作不会把邻近皮肤带走 |
| 表情：眼睑、眉、口 | 局部变形或对齐的表情件 | 与同一个脸部坐标对齐，保留原笔触，必要时提供无五官皮肤底 |
| 提示与光效 | 独立位置、透明度、形变参数 | 与人物分层，明确附着位置和遮挡；不混入邻近角色像素 |
| 固定场景 | 稳定几何与真实轮廓遮挡 | 接触面正确；移动角色部件后仍完整 |

### 5.2 一张部件同时需要三种信息

1. **完整部件图**：包含动作中可能露出的区域。关节后方、被道具挡住的指尖、另一片衣料后面的袖口，要按运动范围补齐。
2. **它移走后露出的底层**：例如衣料、皮肤、背后头发、椅背。底层不能保留原部件的边缘、阴影或旧指尖。
3. **分离边界与连接说明**：提取部件的蒙版、从原位清除它的区域、与邻部件的重叠带和接触点。

完整分层源稿可以直接提供后方下层，无需为每个移动部件重复生成底图。从已合成的插画提取部件时，才需要额外清底和补绘。

提取蒙版与清除蒙版用途不同。前者保留真实细节和抗锯齿，后者必须去掉旧轮廓及随物体移动的投影；两者可以有不同范围。不要用肤色筛选替代手部轮廓，浅色高光、黑色描线和首饰也属于手部。

相邻的脸、肩膀和手可能是同一种肉色，不能按颜色相近把它们并入一层。手部提取沿指尖、掌侧、手腕与前臂的真实外缘走，区分外轮廓与内部指缝；既排除旁边的皮肤和衣料，也保留指尖墨线。逐项检查独立部件与清底，发现残留后回到原图判断归属，不能只把边缘统一收缩到轮廓线断掉。

素材完整到动作范围的并集即可：既不能只画当前可见片段，也不必补画任何情况下都不会出现的整张背面。边缘余量由最大位移、旋转和接缝决定，不能用统一几像素替代检查。

### 5.3 内部切边与真正外轮廓分开

真实人物外缘需要原画描线；关节重叠处、裁图边和蒙版边通常不应额外描黑。补绘时若把颈根、肩部切口画成外边缘，拼接后会出现黑缝和双线。

长发、尾巴和衣摆上的连续线条，不宜在显眼处硬截。拆点应位于自然遮挡或可以连续连接的位置。每个像素确定部件语义归属：肩带留在衣服，耳饰随耳或头，发束随发根；避免把相邻物体一起选入移动层。关节内部允许补画重叠，需去除的是旧姿态残留形成的重复可见轮廓。

盘起的尾巴需要沿尾部实际走向标记固定根部、过渡区和可卷末段，不能只按屏幕横坐标或到尾尖的距离给权重。先检查末段卷起时暴露的裙摆和透明边界，再检查弯曲后的厚度、鳞片与描线是否连续。可参考成熟骨骼动画的[网格权重](https://eu.esotericsoftware.com/spine-weights)与[网格变形](https://us.esotericsoftware.com/spine-meshes)，在已有渲染器内实现当前姿态所需范围。

尾巴先从骨盆后方确定真实根部，即使被衣物遮住也要能追溯连接。沿中心走向检查根部、主体到末端的宽度变化，避免细根接粗段、折角或突然改变弯曲方向；鳞片方向与疏密应随尾面连续。统一不同关键稿的尾根、厚度和鳞片；尾巴不参与当前主动作时，可以共用同一完整尾部，不必随每张姿态稿换图。

部件归属必须沿原图的连续结构确认。肩上的弧形白带可能是从耳后垂下的头发，不能因位置或代码名称而归入衣带或肩膀。沿发根到发梢核对完整像素，先分离发层，再补全其下的皮肤；仅改变前后顺序无法修复一束头发分别烘在两个运动部件里的问题。

清底素材也必须按动作暴露范围检查。静止画面中看不见的旧发根、原肢体边线，在部件移开时会成为残影；补绘底层中同样不能保留这些轮廓。验收同时检查来源、独立层和最终合成，不能把不透明背景误判为发束连续。

前后两个可动部件都要有完整的隐面。例如肩膀前的发束需要独立，发束下要有肩部皮肤，肩膀后也要补全长发；只补皮肤，抬臂后仍可能露出椅背形状的缺口。长发与主体的接缝要跟随主体实际的呼吸、摆动位置，不能只对齐静止坐标。

补全后的部件可能跨越运动区域，需要重新检查绑定归属。完整肩部底图若包含锁骨附近的皮肤，不能整块跟随大臂旋转；内侧与躯干连续连接，外侧再平滑过渡到肩臂运动。否则静止时完整，转动时仍会露出突起、切口或脱离身体的边缘。

关节连接采用共同锚点和受控的重叠带。Live2D 的 Glue 会绑定两个网格的连接顶点并调整影响权重；可借鉴其连接原则，具体模型仍需检查拉扯和形状是否合理。[官方 Glue 说明](https://docs.live2d.com/en/cubism-editor-manual/glue/)

连接检查应覆盖整条公共边及中间姿态。只让两个部件的一点重合，旋转时其余边仍会张开；网格边应沿真实连接边布置，避免规则网格跨过不同运动区域。还要检查目标姿态是否超出连接处的合理空间，不能靠压扁或翻折连接片强行接上。

袖口须保留开口边、包住腕侧的前缘及旋转后显露的内侧布面。仅保留上方一个腕口锚，下面仍可能露出裁切尖角、腕饰拖尾或不该可见的肘。补齐完整接口后，核对整条边在正反运动中的覆盖范围。

### 5.4 表情与眨眼

根据动作范围准备眼球/眼白、眼睑与睫毛、眉、口及必要的皮肤底。左右眼共享动作节奏，但各自按照透视方向和原眼型运动。闭眼线由该角色的眼型决定，没有适用于所有角色的固定高度。

眨眼以眼睑遮挡眼球；不要缩扁虹膜。上眼睑与睫毛同步，下睑按表情需要少量参与，保留眼角和原画笔触。高比例夸张表情可以使用替换件，但必须先对齐脸部坐标与遮挡。

改变注视方向时把虹膜与眼白、睫毛分开，移动虹膜后露出的眼白必须完整。需要明显转移注意力时，用眨眼衔接视线变化并保留短暂停留；等待状态持续看向用户，点击回应结束后回到任务视线。任务进度、暂时回应和自然眨眼可以共用时钟，但不能相互重置，尤其要检查等待中点击和中途返回。

表情蒙版明确包含哪些五官。共用底材之前，分别核对眉、眼、口来自哪个状态；只替换眼睛而意外保留另一表情的眉毛，会改变神态。保留原画可见笔触，补绘只负责原本被遮住的区域。嘴线需在最终光效下比较，避免通过不断加深弥补光效覆盖。

眉毛全程可见时，要连续改变位置、弧度和倾角。闭眼期间换眼部素材不等于可以同时跳换眉毛。两只闭眼线应放回同一脸部透视中审视，以双眼共同的倾斜轴校准内外眼角；不能逐眼套用同一个下降比例，也不能把睁眼上睑的绘制端点当作闭眼时不可移动的端点。否则会出现一眼水平、一眼上挑的问题。闭眼睫毛经过脸侧发丝时，仍要处于真实发丝轮廓后方。

闭眼方向应以最终可见的睫毛笔触检查，不能只验证控制曲线。原画墨线与手工标出的眼缘存在偏差，即使两条控制路径共线，实际眼缝也可能倾角不同。将原生睫毛移动到闭合位置时，应校准墨线自身的位置，保留线宽与睫毛尖，再在头部实际倾角下检查半闭和全闭的双眼。

改变注视对象时，协调眼睑、视线、头姿和短暂停留。可以利用眨眼的闭合阶段切换局部眼部素材；它不能掩盖头发、脸型、脖子同时换成另一张不一致图片的问题。

### 5.5 运动层级与绘制前后分别定义

手指与手掌一起运动，但可能位于道具前方，掌根位于道具后方；镜腿、耳与头发也会交错。将一个完整部件拆成若干绘制子层时，它们仍应共用同一个姿势变换。

同一条肢体可能与一束头发交错：上臂在发后，前臂和手在发前。运动归属一致不代表整条肢体必须放在同一绘制层；在实际重叠区域检查最终可见像素，而不只核对容器名称。

复杂宽袖可沿真实褶线分成少量连续布片，以腕口和共享下摆等实际附着处连接；同一后片也可拆成共用变换的绘制子层，让上部在发后、下部覆盖肘。先按实际遮挡确定分层，避免把会自叠的衣料压进单片网格，也避免把整块袖子放到最前而遮住肩和发束。

掩嘴动作中，裸肩在活动前臂后，袖口布面可以覆盖前臂根部。若一块袖片还带着裸肩，整块放到前景就会盖住手腕；应沿实际袖口边界拆成前后子层，并共用网格和控制点。检查整条公共边，不能让两层各自插值后出现缝隙。这里的顺序由当前接触关系决定，不能照搬成所有动作的固定排序。

可参考 [Spine 的 slots 与绘制顺序](https://en.esotericsoftware.com/spine-slots/)：同一骨骼下的附件可以分别位于另一部件的前后。运动关联与绘制顺序应各自明确。

前后关系随动作变化时，标出发生变化的阶段。换手势优先安排在真实遮挡中，或者画出必要中间姿态；全程可见的肢体不应通过透明度交叉叠出两只手。场景前景按实际外轮廓遮挡，不能只画一个大致三角形。

遮挡内换件也要满足三个条件：新旧部件先共用同一关节位置与方向；交接时两份完整轮廓都被真实前景遮住；交接后逐渐露出的部分已画全。只把图层放到后面，仍可能在道具边缘露出另一套手腕。前臂和腕饰尽量持续使用同一部件，掌面转向只影响掌指范围。若手环抱道具，可让前后显示部分共享同一网格，再用接触区域蒙版区分前后，避免两份独立运动的手越走越散。

验收换件时，除了位置、骨长和网格是否翻折，还要对比交接前后的可见像素，以及正反两条时间路径。用软件逐帧计算确认隐藏范围，再用实际渲染检查蒙版边缘；普通姿势滑块不能替代带有眨眼、停页和手势时序的实播。此处理沿用成熟骨骼动画中[附件](https://us.esotericsoftware.com/spine-attachments)与[网格](https://us.esotericsoftware.com/spine-meshes)分工的思路，具体接触轨迹由当前动作决定。

PixiJS 的 RenderLayer 可以把绘制顺序与父子变换分开；简单场景可继续用现有容器顺序和蒙版。只有出现跨父子层级的排序需求时再使用它。[官方 Render Layers 文档](https://pixijs.com/8.x/guides/concepts/render-layers)

## 6. 简单、可维护的 Live2D 式系统

### 6.1 系统边界

当前需求适合“固定镜头 + 有限姿态 + 分层部件 + 少量动作参数”的二维角色系统。沿用已有 PixiJS 渲染能力，制作自己的角色部件与动作。现有 Mesh 支持顶点和纹理坐标控制，可承担经过设计的局部变形。[官方 Mesh 文档](https://pixijs.com/8.x/guides/components/scene-objects/mesh)

原生Canvas绘制的局部表情或完整动作同样遵循这些职责：控制器管理时间与状态，姿势模块计算运动，渲染模块只组合素材。新动作应在项目的实时预览入口检查，并保留可暂停、可定位时间的审阅方式。

桌面集成参考 CrossPet 的薄原生外壳与共用网页分工：系统窗口行为由外壳处理，角色状态展示与表演共用。它的整图动作和外围特效可提供节奏与辨识度的参考；连续人体动作仍按本文的部件、接触和遮挡规范制作。用户指定项目的源码核对、采用范围与状态语义差异见CrossPet参考记录（制作区：`<art-workspace>/dragon-pet/knowledge/crosspet-reference.txt`）。

素材编辑可以使用成熟绘图软件保存分层源文件。若需求发展到大量自由视角、复杂蒙皮或需要可视化绑定编辑器，再针对该明确需求评估 Cubism/Spine 等成熟制作工具。当前不自建通用编辑器、物理引擎或新配置语言。这里的“Live2D式”描述分层建模思路，现有项目并非 Cubism 格式模型。

### 6.2 四个清楚的职责

```text
真实状态 / 用户交互
        ↓
动作控制器：选择动作、处理时序与打断
        ↓  一帧有明确含义的动作参数
姿势绑定：计算关节、接触、柔性变形与局部表情
        ↓  部件的位置、形状与可见区域
场景渲染：纹理、蒙版、前后顺序、显示尺寸
```

素材与构建单独负责：保存可编辑源稿、完整部件和采用记录，生成运行时纹理。渲染代码不判断客户端是否任务成功，素材文件不携带真实审批结果，控制器不散布裁图像素坐标。

现有 `reading-controller.js` / `work-controller.js`、各自 rig、scene 和 build 已体现这些职责。阅读与工作仍各有自己的实现。复用时先抽出已经出现两次、语义一致的能力，例如眨眼调度、提示符号、时间与暂停；部件姿势保留在各自模型内。

### 6.3 按基础姿态共用模型

同镜头、同身体结构、同道具布局的一组状态共用基础模型。表情、手势和动作参数在它上面变化。角色外轮廓、发型、服装和固定场景尽量来自同一素材源，避免每个状态生成一套互不一致的头与身体。

站立、坐姿、卧姿、不同镜头或不同头身比可以拥有独立的姿态模型。它们共享角色规范、动作含义和渲染能力；无需强行共享每块纹理或网格。跨模型若要表现连续起坐或转身，需要先设计并绘制实际转场；若产品只需切换场景，可采用明确的整体出入场。不要承诺任意两张独立插画自动连续变形。

### 6.4 参数少而有明确归属

参数描述动作，例如头部朝向、眼睛开合、呼吸、某个肢体动作进度、某个道具开合。不要为每个网格顶点建立业务参数。每个模型只实现自己确实用到的参数和范围。

同一参数必须有清楚的控制者。基础姿势先确定，主动作改变它，表情与交互按允许范围叠加，最后添加发尾等次级运动。例如托腮时手腕由接触动作控制；呼吸只能给已允许的区域叠加微动，不能再次拉扯该手腕。

局部排序建议：

| 影响来源 | 处理原则 |
|---|---|
| 最新真实任务状态 | 决定角色正在做什么、是否需停止当前活动 |
| 主动作/过渡 | 管理身体、接触和道具；接管相关肢体 |
| 点击回应 | 在当前状态允许范围内增加回应，完成后回到当前真实状态 |
| 眨眼、呼吸、柔性摆动 | 服从已被主动作占用的部位，避免同一部件被重复变形 |

这是一套确定的合成规则，不需要为所有参数建立通用混合框架。刚性物体的姿势可随手移动，但不能受到头发或呼吸的软变形。

### 6.5 过渡是可被打断的动作

进入新动作前，让当前接触安全收束：正在翻的页落定、触地脚完成承重转移、按下的手指释放。紧急或待处理状态的文字提示可以即时显示，角色完成短暂必要衔接。

可逆阶段的中途反转从当前姿势和速度继续，避免从端点重播。物品已经放下、支撑脚已经切换等接触关系改变后，走预先设计的恢复路径，不能机械倒放。非对称动作可以拥有单独退出路径，例如放下物品与拿起物品的落点和停顿不同。暂停恢复不补播积压的眨眼或点击；重复点击按当前动作合并，不无限排队。

循环、一次性动作、表情与分层变形可以共同使用。循环描述时间组织，拆图描述素材结构；选择应由动作可读性、连续控制需求及制作成本共同决定。

一次性动作要明确完成后的常驻状态。例如唤醒只执行一次，结束后进入持续陪伴，再由常驻时钟安排呼吸、眨眼和点击回应。呼吸等连续动作在状态切换时保留相位，避免重新计时造成一跳；点击回应按当前状态处理，不应每次点击都重新播放完整唤醒。检查范围要延续到动作末帧之后，并覆盖再次休眠、再次唤醒。

### 6.6 状态真实，表演可以有性格

外部事件先确定活动含义和范围，再驱动动作。同一姿态可表现多个含义，例如手持物状态也能等待用户处理；提示文字说明具体情况。没有可验证信号的“推理中”“已成功”不能仅靠时间猜测。

点击角色不等于批准请求。活动结束、连接中断、取消和真正空闲分别处理。Q版和正比共用同一状态语义，各自表达；这让更换形态不改变业务逻辑。

## 7. 从设计到交付的工作流程

| 阶段 | 本阶段交付 | 进入下一阶段的条件 |
|---|---|---|
| 1. 动作说明 | 情境、动作意图、实际触发依据、进入/循环/回应/退出 | 目标清楚；在目标尺寸下有可辨认的主要姿态 |
| 2. 结构草图 | 支撑面、骨架、关节、接触点、镜头与关键帧 | 角色比例、重心、肢体连接与动作范围成立 |
| 3. 部件规划 | 部件表、运动范围、遮挡变化、隐面清单 | 每个会露出的区域有来源，移动后方的下层完整；合成图按需另制清底 |
| 4. 简单动画 | 使用粗稿跑一次进入、保持、退出与反转 | 中间姿态、接触、遮挡成立；无需靠精修掩盖结构问题 |
| 5. 统一精修 | 基于同一模型完成线条、颜色、表情、衣料与完整部件 | 回到参考姿势合成后匹配确认稿，无重复边和色差 |
| 6. 次级动作 | 眨眼、呼吸、柔性摆动、提示与点击反馈 | 不破坏主动作；日常尺寸可见且安静 |
| 7. 最终验收 | 最终打包预览、关键帧、素材索引与明确采用记录 | 美术、结构、运行行为分别验收，用户采纳绑定到确切版本 |

精修前先做最复杂的一次接触或遮挡变化。它通常最能暴露素材缺口。已经能运行的系统继续保留，只增加本动作必需的部件与连接。

使用图像生成时，将整图用作概念和画风参考；生产素材仍要经过分离、隐面补全和对齐。提示词要求“分层”不能让一张普通 PNG 变成真实可编辑模型。补绘限定具体部件和区域，保留采用原图，以蒙版合成局部结果，避免多轮整图编辑累积配色、细节和人体漂移。

## 8. 素材交付与验收

### 8.1 最小交付包

- 一份采用的完整参考画面与比例/线条基准。
- 一份可编辑分层源稿；现有工作流只有 PNG 时，至少保留完整部件、独立蒙版和明确的组合关系，不能声称已有分层源稿。
- 一张部件表：部件名、源图位置、父部件、支点/接触点、刚性或可弯范围、前后关系、最大运动范围。
- 起终点与关键中间姿势，包含隐藏衣物后的结构检查。
- 由实际运行素材生成的动作预览，记录验证范围、尚存限制与采用版本。

源稿、辅助补绘与运行时导出分开。裁切导出应保留在模型坐标中的偏移与支点，不能导出后重新凭眼对齐。替换部件时保持坐标、颜色、轮廓和连接约定；需要改变这些约定时同步修改受影响的动作并重新验收。

命名保持稳定的角色左右和部件含义，例如 `arm_L_upper`、`arm_L_fore`、`hand_L`，实际文件数量由动作需求决定。一份简洁部件表足够，不另建庞大的素材管理系统。

### 8.2 四道验收

**视觉身份与辨识**：在日常实际尺寸观察整个动作，隐藏状态文字后能认出活动大类；在放大尺寸检查笔触和细节。当前桌宠以Q版200px、正比400px为原身体尺度基准，实际日常尺寸按状态统一缩放，见[显示策略](architecture.md)；放大检查到1000px，卧姿按身体尺度与其他姿态匹配。图像分辨率、屏幕显示高度、设备像素比是不同概念；1000px 的界面放大不保证原素材有 2000px 的真实细节。保留原生高清源，并按最大实际显示需求制定导出规格。

**结构与素材**：检查支撑、完整肢体、掌腕或踝足角度、关节宽度、刚性物尺寸、真实外轮廓。检查移动前后是否留旧线、露洞、裁掉耳尖/发丝/指尖，或带入相邻物体。深浅背景与透明背景都要查看；棋盘格只能是检查背景，不能被画进素材。

**动作连续性**：看正向和反向、接触前后、最大弯曲、全闭眼、换素材时刻，以及25%/50%/75%左右的中间位置。再看实际时间播放和中途反转；均匀采样参数不能保证时序正确。检查位置与速度连续、停顿自然、没有双重轮廓、可见肢体透明重叠或刚性物变软。

**运行行为**：用最终打包资产验证启动、暂停恢复、重复交互、状态打断、不同显示尺寸和切换后的资源释放。几何检查可发现翻折、断点和接触误差；截图和人工观看判断人体与表演是否自然。自动检查通过、浏览器检查通过、用户采纳是三个独立结论。

没有翻折也可能看起来像皮肤被拉长：常见原因是衣料下层缺失，或肩肤重叠带过窄。隐藏衣物核对真实肩肘腕，再恢复衣物检查肘、腕口和肩的覆盖；同时看裸露皮肤的宽度、转折与长度。不要靠移动骨点掩盖素材缺口，也不要把正面积检查写成完整视觉通过。

采用记录还须单列正式运行入口的接入状态。用户接受动作后立即记录日期、原话、具体预览、实现与素材路径；不能由“已采用”推断所有状态入口已经换版，也不能把离屏取帧或控制器测试写成浏览器实播通过。检查按风险选取，优先看真实素材和关键运动；无需为一般素材迭代重复生成哈希。

同一任务状态在不同人物比例下可以采用不同表演。先保留姿态中已经成立的支撑、关节和接触关系，再选择小尺寸可辨认的动作。例如短臂角色等待确认可停下当前动作、通过眨眼抬眸与问号表达；只有在关节活动范围与素材隐面都支持时才安排摘镜或大幅托腮。骨长恒定不能证明肩、肘、腕朝向和遮挡自然，必须结合母图及实际中间帧审阅。

### 8.3 扩展新状态的完成标准

新的状态应主要增加自己的关键姿势、必要部件和动作参数，而不是到处修改旧状态的蒙版和像素坐标。若新增表情必须重画整个头，先检查是否缺少共享头部；若每个动作都要补同一片衣服，先检查是否缺少完整底层；若每次都更改前后关系，先检查逻辑父子层级是否被当成了绘制顺序。

新增变化可能影响共用部件时，至少复核共用它的原状态和往返路径。复用不等于让每个姿态共用同一套网格，也不意味着本次修补自动成为所有其他姿态的限制。

| 举书放书颜色突变 | 两端始终共用一份书本与身体材质 | 同一物体持续存在，动作改变姿势，不在端点偷偷换整张纹理 |
| 小臂折断、腕掌夹角接近90° | 统一握点、腕、前臂和腕饰的运动 | 检查连接位置也检查方向，由接触联动整条运动链 |
| 尾巴带动衣服扭曲，旧尾线留在裙上 | 独立尾段、精细轮廓、无尾底层与固定尾根 | 可动柔性物有明确归属、固定区和后方完整底层 |
| 打字像抖动；手移出显示器后少指尖 | 关节分段与触键停顿，补出完整手并放在真实前景后 | 节奏与关节优先，运行时遮挡完整部件 |
| 转头像平移、纸片旋转，进一步变形又拉坏脸 | 缩小到可表达的角度，分开脸、刚性饰品、后发和颈部 | 确定模型转向范围，超出范围准备视角素材 |
| 呼吸拉坏上臂 | 调整影响区域，保护肩臂与接触点 | 次级动作不能重复控制主动作约束的区域 |
| 两眼反向闭合、睫毛消失、闭眼过低 | 按原眼型校准眼缘和睫毛，眼裂遮挡原虹膜 | 每只眼有自己的局部坐标，闭眼保留角色笔触 |
| 托腮手臂拉长、袖底被误作肘；强制二维恒长仍不自然 | 补完整上臂和袖子，隐藏衣料核对肩肘腕，允许合理投影变化 | 真实关节与透视共同成立，衣物不能替代解剖依据 |
| 摘镜捏错镜腿，眼镜大小形状变化 | 右手与右镜腿配对，全程使用同一完整镜框 | 刚性道具保留身份，提前验证抓握位置与可达范围 |
| 切换头部导致头发突变、胸颈割裂 | 统一外发、刘海与脸轮廓，局部眼嘴变化，原衣领和连续颈部衔接 | 同姿态模型共用不变部件，内部拼接线不能当外轮廓 |
| 发丝截断、衣带随头移动、第二条大臂残留 | 延伸完整发束，排除衣带和旧臂，局部补全衣料 | 部件按语义拆分，每块像素只有明确归属，源底图要清干净 |
| 袖子盖错文件、返回握书时手书前后错误 | 按完整前景轮廓遮挡，掌根与指尖分层但同动 | 正反路径都检查，运动父子与绘制前后分别定义 |
| 换握淡化出现双手，直接移到书后又露出错位袖口 | 统一腕点，在道具后切换完整手型，接触前景共享网格与蒙版，腕饰持续使用一份 | 换件需要共同关节和足够遮挡空间，不能靠透明度隐藏连接错误 |
| 收拢衣袖压窄结饰，移走结饰后布面留空 | 补全饰品下面的衣料，让结饰和流苏保持自身比例 | 柔软布面与硬质饰品分别运动，完整底层先于精细形变 |
| 问号气泡夹带龙角，整气泡不停闪烁 | 气泡和字形分离，进场弹跳，常态仅字形摆动 | 提示符号独立资产，进入效果与持续效果分别设计 |
| 嘴线浅，直接加粗后又失真 | 回到原参考的柔和线条，保持原嘴形 | 小尺寸辨识先靠轮廓、构图和节奏，不能牺牲画风补偿 |
| 抬臂时肩根像断开的椭圆或平底皮片 | 固定胸衣侧连接边，活动上臂接到短弧肩根，清除内部旧轮廓 | 肩根连接面与旋转肢段分开；边界应对齐实际补绘后的躯干，不能混用两套衣领轮廓 |
| 长袖跟着上臂翻成横板，掌边带出碎片 | 上臂、前臂与掌、下垂披袖分件，共用明确关节和布料挂点 | 宽衣料不宜只按距离权重跟骨骼扭转；轮廓与隐面同样需要逐帧检查 |
| 掌边带出肉色碎块，掩嘴时手腕被肩膀盖住 | 沿真实手部外轮廓提取，排除相邻脸部和肩部皮肤；肩膀与袖面在袖口处分层 | 同色不等于同一部件；共享运动网格不意味着必须共享绘制前后顺序 |
| 双侧手臂粗细、手型不同，关节前后关系混乱 | 回到同一比例基准重画肩肘腕链和掌块，按每个接触阶段检查遮挡 | 造型一致、骨架成立和前后顺序需要分别检查 |
| 尾根偏离后腰、转折生硬、主体过细且鳞片变淡 | 统一后腰连接、连续中心走向、宽度与鳞片，再供各姿态共用 | 关键稿中的非活动部件也要保持同一结构与材质 |
| 关键稿增加后，动作仍在各节点突然变快或停住 | 按累计转角定位姿态，主要运动段大致匀速，相邻插值段保持速度连续 | 关键稿数量不能替代时间与速度设计 |
| 袖面混合出现重影，结饰被衣料拉长 | 共用一份袖面纹理，补齐结饰下方布面，结饰独立运动 | 持续存在的物体保持材质身份，稳定形状不随柔性表面软拉 |
| 只抬手难以读成伸懒腰 | 先醒眼，再蓄力、联动伸展、明显停留、放松回位 | 表演意图由节奏和身体协同表达；头部保持整体，支撑部位保持稳定 |
| 多轮测试通过，仍被用户指出结构问题 | 加入真实素材、关键中间帧、隐藏袖子的审图与实播 | 数学正确和表演自然分别验收，旧测试不能证明新版本采用 |
| “第一版/第三版”未绑定文件，记录互相冲突 | 本次图录标明已知结构与待核映射 | 用户采用时记录确切文件和预览版本，不从编号猜测 |

## 10. 每次设计都先回答的十个问题

色彩一致性补充（2026-10-31）：颜色基准同时覆盖原始角色参考与当前实际部件。母图正确不代表补绘的手、脸、头发和衣料仍然一致；应分别检查肤色、发丝亮部、阴影色相与描线。保留不同光照的明暗关系。需要最终校色时，同场景的所有姿态完成合成后统一处理，不在动作途中更换色彩参数；跨场景先分别校色，再渐变。透明度和轮廓不应被校色改变，审阅与导出使用同一处理。新素材仍须先保持自身材质一致，最终校色不能修复局部色差。项目实现见色彩统一记录（制作区：`<art-workspace>/dragon-pet/colors/README.txt`）。

肤色明度也须对齐：只修色相而强制保留原亮度，会保留状态间的明暗偏差。先确认实际可见皮肤来自哪一层，例如陪伴脸部来自underlay而非提供眼睛的awake；比较脸、手与唤醒替换件。共同对齐皮肤亮部，同时保留阴影、腮红和局部光照。白发、衣褶和翼膜分别检查，不能为了抬亮皮肤而整幅加亮，或把参考中的淡紫压成灰色。当前项目按用户最新指定的CrossPet GPT六张状态素材校验配色。

1. 这个动作想让用户看懂什么？实际显示大小下靠什么轮廓表达？
2. 角色从哪里来、如何进入、如何停留、如何离开？
3. 重量由哪里支撑？哪些接触点建立、保持、释放？
4. 衣物下的关节和肢段是否连贯，镜头与透视是否一致？
5. 动作中哪些区域第一次露出，是否已经画全？
6. 哪些部件一起动，哪些需要分开画在前后？
7. 哪些部件刚性，哪些可以弯，根部和固定区在哪里？
8. 表情变化能否在同一个脸与头发上完成？
9. 途中被点击、暂停、反转或接到新状态时怎样连续处理？
10. 哪份文件被采用，哪些验收已完成，哪些还只是候选？

这十个问题的答案填入[动作设计模板](state-design-template.md)，作为下一张图的绘制输入与动画交付依据。

## 逐帧审阅补充（2026-10-25）

- 每个完整动作先按实际时间取 10–20 帧，分别检查手部连接、面部肩颈和全身。短眨眼必须单独取样；长片段的均匀取样可能恰好全部错过眼睑闭合。
- 遮挡里缺失的掌根、皮肤、袖面必须先补完整。把可见轮廓当成完整身体轮廓，会在移开遮挡后露出缺口；只改蒙版无法修复缺失的素材。
- 横穿手掌的蒙版可能留下与腕部无连接的肤色孤块。先画出松开、侧转、再握住的接触变化，再决定在道具后交接还是使用侧向手型；不要只根据首尾姿势推断中间遮挡。
- 侧转需要保留掌面厚度和腕部连接，不能把部件压到零宽来掩盖换件。持续存在的腕饰独立运动；检查的是实际可见袖口，不是已经从手掌图层移除的旧袖口坐标。
- 速度改为 2/3 意味着运动时间乘 1.5。只调整需要放慢的肢体段；眨眼、停留、触碰反馈应有各自节奏。反向运动需要保留速度并经过减速，不能立即跳向反方向。
- 把动作的完整时间与分层范围写进审阅记录；自动几何检查辅助发现断口，最终仍需查看实际浏览器画面。保留原路径与新设计的可运行对照，不把试验配置加入正式角色运行时。
